# 离线语音控制工程代码说明

本文说明工程中各模块、类、函数和主要变量的用途。启动方法见 [README](../README.md)，ECSnake 的具体接口约束见 [联动说明](integration.md)。

## 1. 代码目录

建议按下面的顺序阅读：

1. `main.py`：程序入口。
2. `voice_control/config.py`：设备、路径、关键词与业务动作的统一配置。
3. `voice_control/controller.py`：唤醒、指令处理、反馈和退出的完整流程。
4. `voice_control/command_handler.py`：实际业务如何接收指令并返回结果。
5. `voice_control/kws_engine.py`：如何构建并检查识别命令。
6. `voice_control/audio_capture.py`、`audio_feedback.py`：收音与放音。

项目中的 Python 代码主要负责组织流程，实时关键词识别由 sherpa-onnx 的可执行程序完成，收放音由 ALSA 命令完成。

| 文件或目录 | 作用 | 主要调用方 |
| --- | --- | --- |
| `main.py` | 独立启动入口 | `python main.py` |
| `__main__.py` | 包启动入口 | 父目录下的 `python -m photo_test` |
| `__init__.py` | 对外导出五个业务接口 | ECSnake 的 `from photo_test import ...` |
| `voice_control/controller.py` | 管理运行流程和 KWS 子进程 | 启动入口、主应用 |
| `voice_control/config.py` | 集中保存配置及指令映射 | 运行模块和诊断工具 |
| `voice_control/command_handler.py` | 定义业务函数及其结果格式 | 语音服务、ECSnake 适配层 |
| `voice_control/kws_engine.py` | 检查模型文件、构建识别命令 | 语音服务、录音诊断 |
| `voice_control/audio_capture.py` | 设置收音路由，录制和拆分 WAV | 语音服务、录音诊断 |
| `voice_control/audio_feedback.py` | 设置播放路由并播放 WAV | 语音服务 |
| `tools/` | 录音诊断和音量版程序构建 | 开发工具命令 |
| `sounds/create_sounds.py` | 合成固定中文提示音 | 开发机手动运行 |
| `config/` | 关键词文本与 ALSA 配置文件 | KWS 程序、ALSA |
| `sounds/` | 运行时使用的八个提示音文件 | 播放模块 |
| `local_assets/` | 本地生成语音、诊断录音 | 声音生成与录音工具 |

## 2. 程序调用流程

```text
main.py / __main__.py
    → controller.main() 解析命令行参数
    → VoiceConfig 保存运行参数
    → VoiceController.run()
    → _run_listener()
        → realtime_command() 构建唤醒/指令两套 KWS 命令
        → configure_capture_route() 设置麦克风路由
        → wait_for_keyword() 等待唤醒，随后回收本轮 KWS 进程
        → play_audio() 播放问候语
        → wait_for_keyword() 等待指令，随后回收本轮 KWS 进程
        → _handle_command()
            → 将中文关键词转换为 VoiceCommand
            → 调用业务处理函数并取得 CommandResult（如提供了处理函数）
            → 根据结果决定是否播放提示音
        → 继续等待指令，或回到等待唤醒
```

外层循环代表“等待唤醒”，内层循环代表“已唤醒，可以连续使用指令”。“再见楠机”结束内层循环并回到外层；`stop()` 或 `Ctrl+C` 结束整个服务。

识别到关键词后，`wait_for_keyword()` 会先终止识别子进程，释放麦克风，再允许业务处理和播放。这样播放时没有正在运行的 KWS 监听，提示音不会被本轮监听重新识别。持续模式处理一条指令后等待 `PLAYBACK_SETTLE_SECONDS`，再进入下一轮。

### 两种业务处理方式

| 创建方式 | 行为 |
| --- | --- |
| `VoiceController(config)` | 识别指令并播放对应固定音频，不调用相机或机械业务 |
| `VoiceController(config, command_handler=handler)` | 先调用 `handler`，取得成功结果后才播放对应音频 |

`SLEEP` 由语音服务内部处理。业务成功分支播放对应提示音；失败、异常或返回类型错误的分支打印原因，然后继续后续流程。播放命令的异常向调用方传递。

## 3. 核心类的职责

| 类 | 所在文件 | 用途 |
| --- | --- | --- |
| `VoiceCommand` | `config.py` | 用枚举表示稳定的业务动作名称 |
| `VoiceConfig` | `controller.py` | 保存一次服务运行的路径、设备和模式参数 |
| `VoiceController` | `controller.py` | 管理监听生命周期，并协调识别、业务和反馈 |
| `CommandHandler` | `command_handler.py` | 描述业务处理函数应具有的调用形式 |
| `CommandResult` | `command_handler.py` | 保存业务最终的成功/失败结果与说明文字 |
| `ListenerStopped` | `controller.py` | 内部异常，用于从关键词等待流程退出 |

### VoiceCommand：业务动作名称

业务层比较枚举成员，例如 `command == VoiceCommand.TAKE_PHOTO`。需要英文字符串时使用 `command.value`，例如 `"take_photo"`。

| 识别到的中文词 | 枚举成员 | `.value` | 对应音频 |
| --- | --- | --- | --- |
| 拍照 | `TAKE_PHOTO` | `take_photo` | `takephoto.wav` |
| 录像 | `START_RECORDING` | `start_recording` | `start_record.wav` |
| 停止录像 | `STOP_RECORDING` | `stop_recording` | `stop_record.wav` |
| 冻结 | `FREEZE` | `freeze` | `freeze.wav` |
| 测量 | `MEASURE` | `measure` | `measure.wav` |
| 归零 | `RESET` | `reset` | `reset.wav` |
| 再见楠机 | `SLEEP` | `sleep` | `goodbye.wav` |

`RESET` 表示“归零”的业务请求，其执行接口由 ECSnake 适配层提供。

### VoiceConfig：运行参数

它是 `dataclass` 数据类，Python 自动生成构造函数；`frozen=True` 表示创建后不能直接改写字段。修改配置时创建新对象。

| 字段 | 类型 | 含义 | 默认值 |
| --- | --- | --- | --- |
| `sherpa_dir` | `Path` | sherpa-onnx 模型与构建根目录 | `DEFAULT_SHERPA_DIR` |
| `mic_device` | `str` | 实时 KWS 输入设备名 | `kws_left` |
| `speaker_device` | `str` | 提示音输出设备名 | `hw:APE,0` |
| `once` | `bool` | 是否处理一条指令后返回，包含业务失败的情况 | `False` |
| `volume_meter` | `bool` | 是否使用音量版 KWS 并显示输入音量 | `False` |

```python
from photo_test import VoiceConfig, VoiceController

config = VoiceConfig(once=True, volume_meter=False)
voice_controller = VoiceController(config)
# 在程序的工作线程中调用 voice_controller.run()。
```

### VoiceController：服务对象

| 成员或方法 | 作用 |
| --- | --- |
| `config` | 保存本实例的 `VoiceConfig` |
| `command_handler` | 保存业务函数；`None` 表示只进行提示音反馈 |
| `_stop_event` | 跨线程停止标记，初始未设置 |
| `run()` | 阻塞执行监听流程，直到退出 |
| `stop()` | 设置停止标记，可由主应用的其他线程调用 |
| `_handle_command(keyword, sound_path)` | 内部方法：转换业务指令、等待结果、播放反馈 |

名字前的 `_` 表示内部实现。主应用通过 `run()`、`stop()` 管理服务，一个实例对应一个工作线程；重新启动时创建新实例。

`stop()` 设置停止标记，当前业务调用或播放完成后结束流程。工作线程由主应用创建，业务超时由业务处理函数管理。

### CommandHandler 与 CommandResult：业务接口

`CommandHandler` 是 `Protocol`，用于描述接口形式。相机等动作由适配层实现，普通函数或实现了 `__call__` 的对象都可以作为处理函数。

接口形式：`handler(command: VoiceCommand) -> CommandResult`。

| `CommandResult` 字段 | 类型 | 含义 |
| --- | --- | --- |
| `success` | `bool` | `True` 表示业务实际完成；`False` 表示失败或没有完成 |
| `message` | `str` | 终端输出的业务说明文字，默认为空字符串 |

示例：`CommandResult(False, "相机未连接")`。处理函数返回 `CommandResult` 对象，语音服务检查对象类型和 `success` 的布尔类型，再进入对应结果分支。

## 4. 配置变量和资源映射

以下变量均位于 `voice_control/config.py`。

| 变量 | 含义 |
| --- | --- |
| `PROJECT_DIR` | 依据代码文件位置计算的工程根目录 |
| `CONFIG_DIR` | `PROJECT_DIR/config`，保存关键词与 ALSA 配置 |
| `SOUNDS_DIR` | `PROJECT_DIR/sounds`，保存运行用 WAV |
| `DEFAULT_SHERPA_DIR` | 默认 sherpa-onnx 根目录，`~` 展开为用户主目录 |
| `MIC_DEVICE` | 实时输入设备 `kws_left`，提供左声道单声道数据 |
| `SPEAKER_DEVICE` | 播放输出设备 `hw:APE,0` |
| `CAPTURE_DEVICE` | 诊断录音设备 `plughw:APE,0`，录制原始双声道 |
| `AUDIO_CARD` | `amixer` 使用的声卡名称 `APE` |
| `I2S_INTERFACE` | 音频接口名称 `I2S2` |
| `DMA_INTERFACE` | 音频路由端点名称 `ADMAIF1` |
| `WAKE_KEYWORD` | 进入指令模式的中文唤醒词 |
| `SLEEP_KEYWORD` | 返回等待唤醒的中文退出词 |
| `PLAYBACK_SETTLE_SECONDS` | 持续模式下一轮监听前的间隔，单位秒，默认 `0.5` |

设备名称对应 ALSA 软件设备。实时输入提供左声道单声道数据，诊断输入同时保存左右两条声道。

三张映射表分别负责三个层次：

| 映射变量 | 键 → 值 | 示例 |
| --- | --- | --- |
| `KEYWORD_COMMANDS` | 中文关键词 → 业务枚举 | `"拍照" → VoiceCommand.TAKE_PHOTO` |
| `COMMAND_AUDIO_FILES` | 业务枚举 → 音频文件名 | `TAKE_PHOTO → "takephoto.wav"` |
| `COMMAND_SOUNDS` | 中文关键词 → 音频文件名 | `"拍照" → "takephoto.wav"` |

`COMMAND_SOUNDS` 由前两张表自动生成。关键词识别的音素配置位于 `config/*.txt`；添加新指令时同步配置 Python 映射与关键词文件。

## 5. controller 中的主要局部变量

### wait_for_keyword：等待一条识别事件

| 变量 | 含义 |
| --- | --- |
| `command` | 交给 `subprocess.Popen` 直接执行的 KWS 程序与参数列表 |
| `keywords` | 本轮允许接受的中文词集合；唤醒轮次只接受唤醒词 |
| `env` | 子进程环境变量；`None` 表示继承当前环境 |
| `stop_event` | 停止请求标记，循环检查它是否已设置 |
| `process` | 正在运行的 KWS 子进程对象 |
| `chunk` | 从标准错误管道读到的原始字节块，最多 4096 字节 |
| `recent` | 最近最多 16000 字节日志，用于跨读取块匹配关键词事件 |
| `volume_pending` | 尚未完整换行的音量日志片段 |
| `show_volume` | 是否转发 `[volume]` 日志 |
| `matches` | 日志中匹配事件格式且属于允许词集合的关键词列表 |
| `detail` | 进程异常结束时附带的末尾日志文字 |
| `KEYWORD_EVENT_PATTERN` | 提取 JSON 日志中 `keyword` 字段的正则表达式 |

中文 UTF-8 字符或 JSON 事件可能被拆到两次读取中，所以先保存字节，再解码匹配。同一批结果同时出现“录像”和“停止录像”时，代码选择较长的“停止录像”。

退出时先调用 `terminate()`，最多等待 3 秒；子进程仍未结束则调用 `kill()`，随后等待回收并关闭日志管道。

### _run_listener：协调状态循环

| 变量 | 含义 |
| --- | --- |
| `config` | 当前服务实例的配置对象 |
| `greeting` | `sounds/nanji.wav` 的完整路径 |
| `sounds` | 中文关键词到完整音频路径的字典 |
| `sherpa_dir` | 展开用户目录并解析后的 KWS 绝对路径 |
| `meter_options` | 是否向命令构建函数传入 `volume_meter=True` |
| `wake_command` | 加载 `wake_keywords.txt` 的识别命令列表 |
| `command_listener_command` | 加载 `command_keywords.txt` 的识别命令列表 |
| `keyword` | 一次识别返回的中文词 |

使用 `kws_left` 时，`env["ALSA_CONFIG_PATH"]` 指向工程中的左声道配置。启用音量模式时，`env["SHERPA_KWS_VOLUME"]` 使音量版程序输出音量日志。子进程环境字典基于主程序环境的副本创建。

## 6. KWS 与音频函数

### kws_engine.py

| 函数 | 输入 | 返回值或作用 |
| --- | --- | --- |
| `model_files(sherpa_dir, keywords, binary_name)` | KWS 根目录、关键词文件路径、程序名 | `(程序路径, 模型部件路径字典, tokens.txt 路径)`；缺失文件或 token 时抛出异常 |
| `_keyword_command(...)` | 与 `model_files` 相同 | 程序路径和共用模型参数列表 |
| `realtime_command(sherpa_dir, keywords, device, volume_meter)` | 模型目录、关键词文件、输入设备、音量开关 | 返回完整实时识别命令列表，由 controller 启动进程 |
| `recognize_photo(sherpa_dir, keywords, wav)` | 模型目录、关键词文件、单声道 WAV 路径 | `(output, found)`，即日志文字与是否识别到“拍照” |

这里的 `keywords` 类型为文件路径，`wait_for_keyword()` 的同名参数类型为允许词集合。`MODEL_NAME` 是模型目录名，`MODEL_PARTS` 是 encoder/decoder/joiner 部件名，`MODEL_SUFFIX` 是三个 ONNX 文件共有的后缀。

`tokens` 保存词表文件路径，`available` 保存词表已有 token，`required_tokens` 保存关键词需要的 token，`missing_tokens` 是两者差集。关键词文件中 `@` 前是音素 token，`@` 后是中文显示名称，词表检查针对音素 token。

### audio_capture.py 与 audio_feedback.py

| 函数 | 参数含义 | 返回值或作用 |
| --- | --- | --- |
| `configure_capture_route()` | 无参数 | 将 I2S2 输入送入 ADMAIF1 |
| `record_stereo(path, device, seconds)` | 输出路径、录音设备、秒数 | 同步录制 48 kHz、16-bit、双声道 WAV |
| `split_channels(source)` | 双声道 WAV 路径 | 左右声道名称与输出路径列表 |
| `capture_for_kws(destination, device, seconds)` | 输出基准名、设备、秒数 | 录制原始 WAV，再返回拆分后的声道路径列表 |
| `play_audio(sound_path, device)` | WAV 路径、播放设备 | 将 ADMAIF1 输出送往 I2S2，等待播放完成 |

录音基准名为 `photo-test.wav` 时，产生 `photo-test-raw.wav`、`photo-test-left.wav`、`photo-test-right.wav`。诊断工具处理这些 WAV 文件，实时 KWS 直接处理麦克风流。

`samples` 是有符号 16-bit PCM 样本数组。双声道样本交错排列，`samples[0::2]` 为左声道，`samples[1::2]` 为右声道。`rate` 是采样率，单位 Hz；`level` 为 RMS 幅度，单位是 PCM 数值；`clipped` 是绝对值达到 32000 的样本占比，范围为 0～1。

RMS 描述信号强度，削波比例描述近满量程样本占比，两者用于声道诊断。有效语音声道根据识别结果判断。播放函数按 WAV 文件本身的内容与格式调用 `aplay`。

## 7. 工具与声音生成脚本

### tools/photo_check.py

从项目根目录执行 `python -m tools.photo_check`。不指定文件时现场录音；`--wav` 使用单声道文件；`--raw-wav` 先拆分双声道文件。这两个文件选项互斥。

`channels` 为 `(显示名称, WAV 路径)` 列表，`name` 为当前声道名称，`channel_wav` 为输入路径。`output` 为识别日志，`found` 为识别结果。识别到目标词时返回退出码 0，否则返回 1。

### tools/build_volume_meter.py

`source` 是待插入日志的 C++ 文件，`binary` 是原版 KWS 程序，`destination` 是带 `-volume` 后缀的输出程序，`backup` 是原程序临时备份，`original_source` 是用于恢复的源码字节。

`anchor` 是插入位置的精确文本，`METER_CODE` 是 C++ 音量统计片段。`sum_squares` 累积平方幅度，`sample_count` 统计样本数，`peak` 保存最大幅度，`clipped` 统计近满量程样本。约每半秒计算一次 RMS、dBFS 和削波占比。

构建通过临时改动原源码进行，`finally` 会恢复原源码与原可执行程序，音量版单独保存。使用方式见 [音量说明](volume_meter.md)。

### sounds/create_sounds.py

运行命令：`python sounds/create_sounds.py`。脚本联网调用 edge-tts 合成 MP3，再调用 FFmpeg 转换为 WAV，最后删除中间 MP3。提示音生成作为开发工具独立运行，语音服务播放生成后的固定 WAV。

| 变量或参数 | 含义 |
| --- | --- |
| `TEXT` | 要合成的中文文本 |
| `VOICE` | edge-tts 的声音名称 |
| `PROJECT_DIR` | 工程根目录字符串 |
| `OUTPUT_DIR` | `local_assets/` 输出目录 |
| `TEMP_MP3` | 临时 MP3 路径 |
| `OUTPUT_WAV` | 最终 WAV 路径，默认 `local_assets/nanji.wav` |
| `FFMPEG` | 本机 FFmpeg 可执行文件路径 |
| `communicate` | TTS 请求对象，负责合成和保存语音 |
| `rate` | 相对默认语速的调整百分比 |
| `volume` | 相对默认音量的调整百分比 |
| `pitch` | 相对默认音高的调整量，单位 Hz |

当前 FFmpeg 参数为 `-ar 48000`（48 kHz）、`-ac 2`（双声道）、`pcm_s32le`（有符号 32-bit 小端 PCM）。`-y` 允许覆盖生成文件；生成目录与运行用 `sounds/` 分开。`asyncio.run(main())` 用来运行 edge-tts 的异步合成过程。

## 8. 后续修改应该改哪里

| 需求 | 修改位置 |
| --- | --- |
| 调整唤醒或退出词 | `config.py` 的词名及 `config/` 中对应关键词文件 |
| 增加业务指令 | `VoiceCommand`、`KEYWORD_COMMANDS`、`COMMAND_AUDIO_FILES` 和关键词文件 |
| 更换提示音内容 | 修改 `sounds/create_sounds.py` 生成参数，生成后选择替换 `sounds/` 中相应文件 |
| 更换输入/输出设备 | `VoiceConfig`、命令行设备选项；更换硬件路由时同时检查音频配置和 ALSA 文件 |
| 更换 KWS 模型 | `kws_engine.py` 中模型目录与文件名参数，以及匹配模型词表的关键词配置 |
| 接入拍照、录像等业务 | 提供 `CommandHandler` 形式的业务处理函数，传入 `VoiceController` |

ECSnake 接入时，语音工作线程通过 Qt queued signal 请求 GUI 线程执行动作，再等待对应动作的完成、失败或超时结果。拍照根据保存结果返回业务状态；开始/停止录像分别判断录像状态。适配层负责业务连接，收音与播放模块负责音频流程。详细接口见 [integration.md](integration.md)。
