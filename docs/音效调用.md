# 非语音音效调用

`voice_control/sound_effects.py` 提供 `SoundEffects` 播放类和 `SoundEvent` 事件枚举。当前 10 个事件默认选用各自目录的第一版 `01_uisfx_minimal.wav`，风格简洁、短促。后续换音效时修改该文件顶部的 `SOUND_FILES`。

## 事件与调用位置

| 功能 | 枚举 | 事件 ID | 调用时机 |
| --- | --- | --- | --- |
| 拍照 | `TAKE_PHOTO` | `takephoto` | 照片保存成功后 |
| 开机 | `STARTUP` | `startup` | 初始化完成、设备就绪后 |
| 关机 | `SHUTDOWN` | `shutdown` | 必要保存完成后，关闭音频设备前 |
| 开始录像 | `START_RECORDING` | `start_record` | 录像启动成功后 |
| 结束录像 | `STOP_RECORDING` | `stop_record` | 录像文件写入及封装完成后 |
| 冻结画面 | `FREEZE` | `freeze` | 画面进入冻结状态后 |
| 测量完成 | `MEASURE_COMPLETE` | `measure` | 测量结果生成并显示后 |
| 开始检测 | `START_DETECTION` | `start_detection` | 检测模块启动成功后 |
| 停止检测 | `STOP_DETECTION` | `stop_detection` | 检测模块停止成功后 |
| 开始复位 | `START_RESET` | `reset_started` | 控制器接受并开始执行复位时 |

## 已接入的触发与顺序

`VoiceController` 在业务处理函数返回 `CommandResult(True)` 后，按事件播放以下反馈：

| 事件 | 默认顺序 | 当前接入 |
| --- | --- | --- |
| 拍照 | 短音效 → 拍照成功语音 | 照片保存成功后 |
| 开始录像 | 开始录像语音 → 短音效 | 录像启动成功后 |
| 结束录像 | 短音效 → 录像保存语音 | 文件保存完成后 |
| 冻结画面 | 短音效 → 冻结状态语音 | 画面冻结成功后 |
| 测量完成 | 完成语音 → 确认音效 | 测量结果生成后 |
| 开始检测 | 开启状态语音 → 确认音效 | 检测启动成功后 |
| 停止检测 | 停止状态语音 → 确认音效 | 检测停止成功后 |
| 开机、关机 | 预留 | 等待主程序实际生命周期回调 |
| 开始复位 | 预留 | 等待电缸开始执行状态回调 |

短音优先的操作先提供即时听觉反馈，再说明结果；开始录像、测量与检测先说明完成或运行状态，再用短音收尾。以上是当前默认搭配，试听后可逐项调整。

触发关系集中在 `COMMAND_EFFECTS`；`None` 表示该动作等待状态回调接入。先语音的动作放入 `VOICE_FIRST_COMMANDS`，其余已映射动作先播放音效。

业务失败或异常时输出原因。某项 WAV 配置为空时跳过该项：语音为空仍可播放音效，音效为空仍可播放成功语音。

命令行独立运行沿用提示演示模式，以相同顺序播放；连接 ECSnake 时，业务适配层提供实际完成结果。当前复位处理函数返回的是最终结果，开始复位音效留给实际开始状态触发。

## 选择 WAV

相对路径以工程 `sounds/` 目录为起点，也支持绝对路径。例如选中柔和拍照候选后，将配置改为：

```python
SoundEvent.TAKE_PHOTO: "tones/candidates/takephoto/02_uisfx_soft.wav",
```

空字符串表示暂未选音，调用 `play()` 返回 `False`；播放完成返回 `True`。事件 ID 与 [候选目录](../sounds/tones/README.md) 对应。

## 创建与调用

从当前项目根目录导入：

```python
from voice_control.sound_effects import SoundEffects, SoundEvent

effects = SoundEffects()
try:
    # 主程序初始化完成后调用。
    effects.play(SoundEvent.STARTUP)

    # 照片保存成功的业务回调中调用。
    effects.play(SoundEvent.TAKE_PHOTO)

    # 关机流程完成必要保存后调用，播完再关闭设备。
    effects.play(SoundEvent.SHUTDOWN)
finally:
    effects.close()
```

实例在主程序启动时创建并长期复用；首次播放已配置音效时启动持续输出流，空闲时保持静音。也可以使用 `with SoundEffects() as effects:` 自动回收资源。

`play()` 是同步调用，放在业务工作线程执行。界面通过信号或任务队列提交音效事件，由同一个音效工作线程依次调用。语音监听的暂停与恢复由主程序协调。

从 ECSnake 根目录导入时使用 `from photo_test.voice_control.sound_effects import SoundEffects, SoundEvent`。本类提供供业务调用的入口，主程序按上表的成功回调接入。

## 共用已有播放流

主程序已有启动完成的 `ContinuousPlayback` 时，可以传入同一实例：

```python
effects = SoundEffects(playback=playback)
effects.play(SoundEvent.MEASURE_COMPLETE)
```

共享模式的播放流由主程序启动和关闭。选音配置与原语音提示配置分别保存在 `SOUND_FILES` 和 `COMMAND_AUDIO_FILES`；语音控制器统一调用两种反馈，并按事件顺序播放。业务适配层返回结果，语音控制器完成该次反馈。

## 验证

```bash
python -m unittest tests.test_sound_effects -v
```

检查空配置、10 个事件的播放、路径定位、输出流复用、共享资源生命周期和错误处理。`tests/test_feedback_sequence.py` 验证各事件的反馈顺序、实际完成结果及预留触发位置。测试使用模拟播放流和临时 WAV；扬声器试听在选音及部署后进行。
